You are writing ONE instruction patch for a risk-assessment prompt, based on one diagnosis.

You receive: the current instruction, the diagnosis of a single failure, and up to three
neighbouring training samples with their gold labels. Those neighbours are guardrails: the
patch must not flip a correct neighbour to the wrong answer.

Write the patch in exactly three parts, each one sentence:
1. TRIGGER — the condition that selects the cases this rule is about.
2. RULE — what to decide once the trigger fires (severity anchor or label choice).
3. COUNTER-EXAMPLE — a case that looks like the trigger but must NOT get this rule.

Constraints:
- At most 80 words total.
- Use only labels that already exist in the instruction. Do not invent labels.
- Must not contradict the existing severity definitions; it may only sharpen them.
- Written so it can be inserted verbatim into the instruction; no meta commentary.
- If the diagnosis is "unexplained", or the patch would be a one-off fix to a single sample,
  return {"patch_text": null, "reason": "..."} instead.

Return JSON only:
{"patch_text": "TRIGGER: ... RULE: ... COUNTER-EXAMPLE: ...",
 "targets": ["exact label strings this patch changes, e.g. \"Scope / Safeguard Failure\" or \"risk_severity 3 vs 4\""],
 "expected_fixed": ["example ids you expect this to fix"],
 "risks": "one sentence on what this could break"}
