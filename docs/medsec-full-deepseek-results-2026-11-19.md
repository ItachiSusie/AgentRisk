### 交互协议局限及令牌用量

复核 Med 运行的 `runs/*/outcome.json` 和 `runs/*/events.jsonl` 后发现，1,848 次攻击条件中有 **1,375 次以 `invalid_action` 结束**，其中 **1,178 次仅有一次模型响应**；174 次干净基线中也有 77 次以此状态结束。常见返回是一次给出多项动作或多个 JSON 对象，而当前 Med 合成轨道要求每次只返回一个 JSON 动作，解析失败即终止。按既定评分协议，这些是可观察的模型与工具协议失败，故保留在完成运行与可评价分母中；但是，大量早停会压低令牌用量和干净效用，并限制非记忆入口攻击结果的解释力度。Med 的 592 次可评价攻击条件中有 217 次 `invalid_action`（无防御 97/288，scope 120/304）。

Health 容器轨道的 756 次试验通常有 3–5 次以上模型响应；Med 的 2,061 次试验中有 1,249 次仅有一次响应。两轨共 **7,187 次**带用量的模型响应，提示令牌 **2,852,352**、完成令牌 **505,474**、合计 **3,357,826**。提示令牌中 **1,460,594** 被 API 标记为缓存命中；缓存影响计价，不能从令牌总数直接推算费用。下一版若要衡量完整交互下的安全性，应新建有版本号的提示和执行器，为格式错误提供反馈并继续交互，再用新 `run_id` 重跑；本版冻结的提示和结果不覆盖。

### 轨迹长度与可用字段

一条轨迹（trace，一次任务试验从模型请求到结束的有序事件记录）对应一个来源、干净或攻击条件运行；一个回合（turn，一次模型请求及其响应）不一定产生合法工具动作。以下统计由 Med `v17-med-20261119T073649Z-0175ebf0` 的 `runs/*/events.jsonl` 和 Health `v12-health-20261118T060836Z-b3d3cb98` 的 `jobs/*/*/agent/medsec-events.jsonl` 中的 `model_response`、`model_action`、`final_answer` 与 `observation_presented` 事件计数；工具动作数排除 `finish`。

| 轨道 | 轨迹数 | 回合：平均 / 中位 / 范围 | 工具动作：总数 / 平均 / 中位 | 工具反馈总数 |
| --- | ---: | ---: | ---: | ---: |
| Med | 2,061 | 1.73 / 1 / 1–8 | 1,496 / 0.73 / 0 | 1,496 |
| Health | 756 | 4.80 / 5 / 3–12 | 2,876 / 3.80 / 4 | 2,876 |

只看攻击条件，Med 的 1,848 条轨迹平均 1.69 回合、中位 1 回合，共 1,277 次工具动作；Health 的 672 条轨迹平均 4.87 回合、中位 5 回合，共 2,601 次工具动作。轨迹数是不同运行条件的数量，同一个目标任务会因候选和防御条件重复，不能当作同样数量的独立医疗场景。

Health 的 1,496 次实际终端命令执行另有 `command_executed` 记录；其余工具动作包括读取技能和记忆。Med 的 1,249 条单回合轨迹没有合法工具动作，主要受上述动作格式早停影响。当前两轨保存模型请求、原始响应、可解析动作、权限检查、工具反馈、攻击触发和交付结果，能够分析可观察的动作与环境反馈。模型接口在 [`src/medsec/v08/models.py`](../src/medsec/v08/models.py) 中设置 `thinking=disabled`，事件没有独立推理文本字段；这些轨迹**不包含可用的模型内部推理过程**。后续若需研究决策依据，应新建版本，要求模型输出简短、结构化的证据引用和行动理由，并与工具动作一起记录；这仍是模型给出的解释，不等同于内部思维链。

按[医疗风险类别 v1](medsec-medical-risk-taxonomy-v1.md)，Med 的“临床来源污染”代理任务为两条件各 144/144；“患者身份错配”和“越权披露病历”的可评价代理任务均为 0。Health 的“临床来源污染”代理任务为两条件各 48/48；“越权披露病历”为无防御 2/252、scope 0/252。医嘱操纵、危急结果漏处置、越过临床复核没有独立任务及判定，本实验状态为 `not_evaluated`。这些标签是未经临床审核的合成代理结果。
