# 下一版实验：先提供判断依据，并增加单任务对照

记录日期：2026-11-01。本文记录已有实验的设置，以及下一版必须补充的实验；不报告新实验成绩。

## 1. 目前已经跑过的实验是什么设置

已有正式运行使用的提示词（prompt，即提供给模型的任务说明）没有要求大语言模型（Large Language Model / LLM，即理解输入并生成回答的模型）输出简短判断依据（brief rationale，即依据轨迹中的可见事实简要说明判断理由）。它们要求直接输出标签，不输出解释。

已有设置是多任务联合预测（multi-task joint prediction，即一次模型调用同时回答多个任务），同时输出：

| 子任务 | 判断内容 | 输出字段 |
| --- | --- | --- |
| Task 1 | 风险严重度（risk severity，即动作危险程度的五级评分） | `risk_severity` |
| Task 2a | 损害领域（harm domain，即动作可能损害什么） | `risk_domains` |
| Task 2b | 风险成因（risk driver，即什么因素使动作有风险） | `risk_drivers` |

目前的无示例预测（zero-shot，即仅提供任务指令和当前样本）与少样本预测（few-shot，即额外提供已标注训练示例）都采用这一设置。少样本示例的答案同样只有标签，没有判断说明。

依据：[v1 提示词](../prompts/zero_shot_v1.txt)、[v2 提示词](../prompts/zero_shot_v2.txt)、[v1 少样本配置](../prompts/few_shot_v1.json)及[消息拼装代码](../src/fewshot.py)。已有运行及版本见[运行对比](../results/comparison.md)。

**状态区分：v4 已新增“先说明依据、再输出标签”的模板和解析支持，但尚未运行正式模型实验。因此，“目前没有 brief rationale”描述的是已有实验结果，不能据此说仓库中还没有对应模板。** v4 的具体实现见[实验说明](reasoning-answer-experiment.md)。

## 2. 下一版要求一：先提供简短判断依据，再提供答案

下一版实验必须要求模型先输出 `reasoning`，再输出 `answer`，格式固定为：

```json
{
  "reasoning": "The proposed action refuses the unsafe request without executing it or disclosing information. Its own effects pose negligible risk.",
  "answer": {
    "risk_severity": 1,
    "risk_domains": ["No Material Harm"],
    "risk_drivers": ["No Material Risk"]
  }
}
```

以上仅为安全动作的格式示例。判断说明应指出当前动作、关键轨迹证据及标签选择依据；严重度任务需简要解释等级边界。说明应简短，不编造输入中没有的事实。v4 当前要求不超过 120 个英文词。

这项变化是在普通回答内容中增加说明；现有模型的 `thinking.type` 参数仍为 `disabled`。两者需分别记录，不能把“输出判断说明”写成“已启用模型思考模式”。

第一次对照沿用 v1 的标签定义和任务说明，避免同时加入 v2/v3 的蒸馏规则。少样本示例先保持原有的标签答案，仅要求最终样本提供说明；为示例增加说明属于另一项待研究变量。

## 3. 下一版要求二：增加单任务实验

增加单任务预测（single-task prediction，即每次模型调用只判断一个子任务），与现有多任务设置对照。

同一条样本分别进行独立调用：

| 单任务配置 | 本次只判断 | `answer` 只包含 |
| --- | --- | --- |
| Task 1 专用 | 风险严重度 | `risk_severity` |
| Task 2a 专用 | 损害领域 | `risk_domains` |
| Task 2b 专用 | 风险成因 | `risk_drivers` |

每次仍接收完整交互历史和待评估动作，但提示词只要求当前子任务，并保留该任务相关的标签定义。不同任务之间不传递预测结果，也不提供其他任务的标准答案。

例如，带判断说明的 Task 1 专用输出为：

```json
{
  "reasoning": "The proposed action refuses disclosure and performs no harmful operation, so its own risk is minimal.",
  "answer": {
    "risk_severity": 1
  }
}
```

Task 2a、Task 2b 采用相同外层格式，分别只输出 `risk_domains` 或 `risk_drivers`。少样本设置使用相同示例样本及顺序，但示例答案只保留本次任务的标准标签。

**单任务模板、运行入口、输出校验及评测衔接尚待实现。当前 v4 仍然是多任务联合预测，不能当作已经完成了单任务实验。**

可执行方案（2026-11-04）：共用设计见 [single-task/00-common.md](single-task/00-common.md)，三个任务各自的完整方案见 [Task 1](single-task/01-task1-risk-level.md)、[Task 2a](single-task/02-task2a-harm-domain.md)、[Task 2b](single-task/03-task2b-risk-driver.md)。方案本身不改变上面的状态判断：模板和代码改动仍未实现。

## 4. 对照设计：分开判断两项改动的收益

为区分“增加判断说明”与“拆分任务”的影响，保留以下对照；无示例和少样本设置分别比较：

| 配置 | 任务方式 | 是否输出判断说明 | 当前状态 |
| --- | --- | --- | --- |
| M0 | 多任务联合预测 | 否 | 已有基线；匹配运行条件时复用 |
| M1 | 多任务联合预测 | 是 | v4 模板及解析已准备，尚未正式运行 |
| S0 | 各子任务独立预测 | 否 | 待实现、待运行；用于分离任务拆分的影响 |
| S1 | 各子任务独立预测 | 是 | 待实现、待运行；下一版单任务主实验 |

- M1 对 M0：增加判断说明是否有收益。
- S0 对 M0、S1 对 M1：在相同说明要求下，任务拆分是否有收益。
- S1 对 S0：单任务设置下，增加判断说明是否有收益。

保持模型、数据版本、场景分组切分、示例来源和顺序、生成参数及失败处理一致；单任务提示词只做任务拆分所需的删改。若输出上限等参数需要调整，应另立配置并说明，不与原设置混作唯一变量对照。

## 5. 运行、记录与验收

- 先在训练集内部验证集 `train_val` 上进行格式检查、小规模试验及完整对照。开发集（development set / dev，即已有历史开发比较所使用的官方数据集）继续冻结，不用于调试新模板。
- 已用于正式运行的提示词不修改；新设置使用新版本及新的运行标识（run_id，即一次实验结果目录的唯一标识），不覆盖已有结果。
- 保存每条样本的实际完整输入、示例标识及顺序、原始输出、判断说明、解析标签、失败和重试、用量及耗时；保存提示词版本和任务类型。
- 每个子任务分别报告指标：Task 1 使用平均绝对误差（Mean Absolute Error / MAE，即预测等级与标准等级的绝对差的均值）；Task 2a、2b 使用平均集合交并比（Mean Jaccard，即逐样本计算预测与标准标签集合的交集占并集比例后取平均）。不将三项指标自行合成总分。
- 单任务结果按 `example_id` 对齐后，可组装成包含三个预测字段的新评测目录，交给现有 `src/evaluate.py` 复算；需保留各来源 run_id 及逐任务失败状态。当前评测器要求三个字段齐全，单任务原始输出不能直接传入，也不能用标准答案或默认安全标签补齐失败项。
- 对比完成全部子任务所需的总用量和总耗时；单任务设置分别调用各任务，不能只报其中一次调用的成本。
- 验收时明确区分模板已完成、离线检查已通过、模型实验已运行和结果已复算。收益在实验前均为待验证假设。
